# DOM-Evidenced Partial-Load Flag

Platform adapters MUST set `isPartiallyLoaded: true` only when an unexpanded reply subtree is directly evidenced by elements already rendered **inside `#comment-tree`** of the extraction root: an unclicked `shreddit-more-comments` trigger, a `shreddit-comment-tree-action` containing a rendered trigger, a "more comments" / "more replies" button, or a loader fetching the comments endpoint. A loader directly in the tree counts as evidence; inside a single comment it counts only when it is a reply loader or its `bundlename` mentions comments/replies — author hovercards are excluded. An empty action wrapper with no rendered trigger is inert and is not evidence.

Adapters MUST NOT infer partial state from `<shreddit-post comment-count>`, which includes removed, spam-filtered and shadowbanned comments that never produce DOM elements. This refines the `DOM-Availability Extraction` rule: "speculating on unhydrated host SPA state" means count-based guessing, whereas observing a rendered, unclicked pagination element is synchronous DOM fidelity, consistent with ADR-0004's truncation-metadata requirement and <50ms snapshot guarantee. No programmatic clicking or scrolling is performed.
